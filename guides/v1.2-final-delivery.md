# Entity Resolution Atlas v1.2+ — original-task delivery

## Scope and honest completion boundary

This report reconciles the comprehensive v1.2+ expansion task with the implemented
repository. It is a handover document, not a sixth knowledge-object type, a new
roadmap or an authorization to change a consumer project.

**Implemented:** Wave 0–5 knowledge/navigation/documentation tooling, connected
alternatives and evaluation routes, integration templates and a separately frozen
AU-v2 evaluation package. Important specialist gaps have explicit technical
boundaries below and in the [coverage matrix](decision-coverage-matrix.md).

**Verified behavior:** the documentation and evaluation-infrastructure checks in
[final delivery validation](../validation/v1.2/final-delivery-validation.json).
Their scope is metadata/navigation, provenance, protected bytes and synthetic
infrastructure behavior, not scientific certification or agent improvement.

**Unestablished:** the requested empirical improvement in agents' decision quality,
reading/research effort, ER accuracy and operational performance. No AU-v2 solver
run or independent assessment has completed. Section 8.3 requires honest reporting
if independent tests cannot run, and deliverable 8 is conditional on actual
execution. Neither readiness tests nor historical AU-v1 outcomes substitute for
this missing evidence. The unfinished runtime/evaluator work remains disclosed;
it is not silently reclassified as a successful experiment or an extra prerequisite
for handing over the already implemented knowledge expansion.

## Review, validation and claims of benefit

Earlier scientific reviews are inherited with their recorded limits, not relabeled
as fresh full-corpus certification. Wave 1 and 2 critiques/dispositions, Wave 3
author-only passes, Wave 4's four major/two minor separate-critique findings and
remediation, and integration reviews are linked from the final review/tracker.
The delivery review revisits selected no-label/experimental and algorithm-selection
families plus operational/consumer boundaries. It does not inspect evaluator keys
or retune knowledge to the frozen test answers. Separate critique identities are
unattested; post-remediation author checks are not independently certified approval.

The validation report contains actual test counts, generator/lint/citation outputs,
source/card/ID reconciliation and protected-file comparisons. Advisory lengths
and keyword hints remain; passing structure and rendered Sources do not establish
that every scientific statement is correct. Existing literature verification scopes
are retained; no new literature result or “latest version” is asserted by this
handover.

**Theoretical expectations:** selective routes may reduce redundant reading;
independent acquisition and explicit denominators may prevent unsupported claims;
contracts/versioned artifacts may make experiments and repairs more defensible.
These are conditional mechanisms, not measured gains in quality, time or money.

## Actual agent-utility evidence and exact residual work

Historical AU-v1 has 33 validated scored responses for its historical arms, with
mixed findings and disclosed model/transport limitations. It is preserved, not
rerun, rescored or transferred to v1.2. Its known failure modes motivated explicit
identity/attribute, utility/truth, candidate/population and sampling boundaries;
retrieving relevant material did not itself establish correct reasoning.

AU-v2 has eight fictional cases/keys, eight ordinal dimensions, ten schemas and an
externally anchored frozen package. Equivalent-policy snapshots contain 31 baseline
cards, 57 expanded cards and no-Atlas empty context. The frozen 24-cell preparation
plan is not a run registry. Solver inputs/keys/results stay outside the author and
consumer retrieval context. The selected export excludes task/integration guides,
so that comparison would not measure those guides' contribution.

Offline broker/protocol and mechanical blinded-packet/score tools were implemented
and tested synthetically. No full compatible process/transport, actual registered
model/version/settings/conflict evidence or eligible independent evaluator invocation
exists. Requested CLI strings/declared hashes and a fresh process do not meet those
requirements. Scoring does not automatically load registration evidence/executable
bindings; that separate prerequisite cannot be inferred from its acceptance.

Actual AU-v2 runs/scores: **zero**. No new provider call establishes whether earlier
HTTP 402 failures still apply. The residual [runtime/evaluation handoff](../validation/v1.2/au-v2-remaining-work.md)
is retained, not an excuse to fabricate a winner or indefinitely add infrastructure
to the universal knowledge base. Before a real comparison: establish compatible
trusted execution/containment and evidence bindings, pre-register genuine independent
identities/settings, execute every frozen cell, score genuinely completed responses
independently and report case/dimension outcomes, failures/costs and uncertainty.
Any change to protected historical source requires its separately defined scope;
no commit/push or historical overwrite is part of this handover.

## How an external coding agent should use the expanded Atlas

1. Inspect the consumer project's requirements **and current implementation**;
   resolve identity/namespace/time, label/error-cost, access and downstream unknowns.
2. Open one relevant [task section](agent-task-patterns.md) or [L0](../CATALOG.md)
   route. Use only relevant L1 slices, selected Decisions and baseline/alternative
   Solutions, then matching Evaluations/Hypotheses. Use L3 for unresolved detail.
3. Check hard prerequisites, optional context, incompatibilities and stage
   interactions. Keep topology/scoring/resolution/lifecycle choices independent.
4. Fill the [project-local note](project-atlas-integration.md): known/assumed facts,
   mechanisms/options/costs/failures, affected contracts and missing evidence.
5. Specify a controlled experiment using the [plan](experiment-plan-template.md)
   and [realized manifest](run-manifest-template.md): comparator, fixed/changed
   stages, labels/population/denominator/split, uncertainty/practical margins,
   guardrails and positive/negative/inconclusive next decisions.
6. Implement only within actual project authorization. Report what was changed,
   executed, measured or left unproven; use reversible bounded evidence collection
   when semantics, authority, closure or severe-error effects are unresolved.

The universal Atlas supplies reasoning routes, not domain facts, production
permission or a proven winning method. No additional corpus volume, newer model
or passing lint changes that evidence boundary.
