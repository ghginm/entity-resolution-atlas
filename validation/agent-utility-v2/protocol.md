# AU-v2 protocol — frozen data design, not an executing harness

## Authority, separation and novelty
This separately versioned cohort is AU-v2 / package 2.0.0. AU-v1 is untouched and its results are not evidence for AU-v2. Eight fictional cases and keys were authored from general ER reasoning, without new Atlas cards, prior scenario inputs, evaluator keys, score files or result files. Only repository AGENTS.md and the AU-v1 README were read as public separation/protocol context. The author was therefore exposed to the README's public case labels, status and headline summaries; this is not a claim of complete blindness to all historical information. No empirical independence or novelty measurement has been made. Scenario content is not copied from prior cases; their cases, keys and answers were not inspected.

All package artifacts, including apparently public inputs, prompts, schemas, tools and protocol, are EVALUATION INFRASTRUCTURE, never corpus knowledge. The whole validation/ tree and every evaluation artifact wherever located must be excluded from all future corpus exports and corpus-author retrieval. The eight input files and common prompt are exported individually only at run dispatch, not made discoverable in a corpus. Evaluator-only content, including rubric, keys, coverage and evaluator prompt, never enters solver context. Freeze before testing; no response or score has been obtained. No corpus card changes may be based on this cohort's keys or answers.

## Execution eligibility — currently BLOCKED / unimplemented
This is a DATA PACKAGE. There is no AU-v2 runtime, model adapter, corpus export, registered identity, score, or result. No AU-v1 command is asserted to accept these schemas. A later integration must explicitly map these contracts to an independently reviewed existing runtime and verify its behavior before any genuine execution; do not silently run AU-v1 on AU-v2 files and do not build a second agent runtime here.

Before execution, register tested and evaluator provider/model/version identities from actual attested sources, settings and independent context evidence. All identities/providers/models in package preparation metadata remain null/unregistered. Do not infer them from a profile, current host, role label, default model, transport init echo, or author prose. Require distinct tested/evaluator actual model identities and fresh disjoint processes/conversations; an identity alias alone is insufficient. Require an independent evaluator with no author/corpus-writer/tested-agent role and a signed conflict declaration. Author model identity is currently unknown, not presumed distinct: the operator must resolve applicable author/evaluator independence evidence rather than claim it from missing values. If required identity or actual settings cannot be established, do not execute or claim model independence. Reject silent provider/model fallback or identity mismatch; retain a failed attempt if spawning occurred.

Register the actual pinned temperature/top_p/seed/output cap or explicit unavailable/null values and provider defaults with request/wire/attested/unavailable evidence per setting. Distinguish wire-enforced, attested-only and unsupported settings; a self-report cannot prove enforcement. Unavailable settings may be consistently disabled/defaulted only with a predeclared cross-arm equivalence attestation and disclosed limits; inability to establish comparable settings blocks execution. Require actual run-time identity and generation evidence, not just a requested model identifier. Mechanically record prompt/settings/freeze/inventory/runtime/adapter hashes before the first response. Corpus snapshots and registration are new external artifacts, not edits to this package.

## Corpus preparation and equivalent arms
Prepare independent immutable baseline-atlas and expanded-atlas snapshots and an empty no-atlas inventory. No such snapshot is included here; do not infer baseline from current files. Pin snapshot provenance and hashes before testing. No live repository access. Match layer policy, format, file-selection eligibility, generated metadata-only L0, exposure budgets, and broker behavior between Atlas arms; only eligible knowledge contents differ. Rebuild L0 from allowlisted metadata to avoid raw catalog/README/AGENTS pointers. Exclude validation/, evaluation outputs, tests/, tools/, dev_docs/, change logs, coverage/tracker documents, operational/implementation notes, scenario lists, answer/review/opportunity notes, author commentary, and any other evaluation artifact. Allow only declared knowledge card/domain-index/deep-dive/reference paths after a leakage review. Any referenced out-of-inventory path stays unreadable. No blanket repository export. Expanded knowledge may increase available files, not initial stuffed context. The no-atlas arm has the same task and limits but empty inventory and no replacement tutorial. Its retrieval dimension is not applicable, not zero.

Use the same scenario bytes, common prompt bytes, tested identity, generation settings, initial-message format, tools/absence of tools, budgets and isolation in all three arms. Initial messages contain only that one input, common prompt, permitted settings hash/read contract and neutral inventory path/layer/size metadata; no arm label, key, rubric, other inputs, history, author analysis or direct repository path. Neutralize version-revealing filenames where feasible; log mapping outside solver access. Do not claim perfect blinding: retrieved content can reveal version/coverage. Hold evaluation prompt/rubric/key constant across arms.

Eight fixed scenario IDs, one repetition per arm; the settings file declares a three-position Latin rotation of arm order by scenario index. Planned coverage is 24 cells, not 24 executed runs. Use a fresh process, conversation, home/cwd and minimized environment for every cell. Strip memory/history/direct tools; credentials are available only to a trusted transport outside model-visible context. Pin and attest its zero-direct-tool registry. The model has only broker read requests and final text, never shell/network/raw filesystem. The broker is not an OS sandbox: untrusted adapters need external containment, and process freshness alone cannot prove remote context isolation.

## Broker contract to be implemented and verified by future integration
All offsets/lengths are Unicode codepoints; initial/final sizes are characters, stdout lines bytes. Treat input as strict JSONL with no extra stdout chatter. Require a ready attestation with actual identity, fresh_context=true, broker_only=true and matching settings SHA before reads/final. A read request has type=read_file, request_id, exact inventory path, offset>=0 and length>0. A successful broker response has type=read_result, request_id, path, offset, text, returned_characters and content_sha256 (UTF-8 bytes of returned text). A denied response has type=read_denied, request_id and reason, no leaked content. A final has type=final and text, followed by successful transport exit with no subsequent messages. Retain exact request/response/log bytes and trusted timestamps.

Deny traversal, absolute paths, symlinks, aliases, undeclared files, keys and paths outside the snapshot. Count every request attempt, every successful read, repeated content, returned characters and chunk length; limits and wall/line/initial/final budgets are frozen in settings.json. Budget excess fails closed, not a truncated answer counted as completed. Log the path, offset/length, returned text hash, requested inventory hash and counters. Validate each file against its immutable snapshot hash before return. Verify zero inventory in no-atlas and deny all reads there. Retain failed attempts and partial logs as failures, not successful completions.

## Comparison and recovery
Preregister planned cells and use this deterministic reporting rule: include every attempted/failed/unexecuted cell; use the first completed attempt from the earliest full cohort as the exploratory comparison sample. Do not selectively retry a promising arm. If transport blocks a cell, preserve the cohort and preregister a fresh complete 24-cell recovery cohort with unchanged frozen data/settings; retain extra completions as disclosed additional samples, never overwrite or backfill invisibly. New run directories and records must be exclusively created. A provider/settings change is a separately registered cohort, not an equivalent hidden retry. No repeated seeds exist in this package; one repetition supports exploratory contrasts, not statistical-significance claims.

## Blinded independent scoring
Only real completed responses may be scored. A future trusted packet builder verifies run/freeze/read hashes and exports a neutral packet with scenario, task, response, authorized read excerpts/logs, matching key, rubric and provenance hashes. Remove arm/order/provider/model/adapter identifiers, timestamps and corpus labels from evaluator-visible content. Preserve needed evidence; do not add author conclusions. An operator outside the packet checks evaluator independence and identity. Evaluator packet generation and score validation are NOT implemented by verify.py.

Use evaluator-only/prompt.txt and schemas/score.schema.json. Ordinal dimensions are independent 0–3; retrieval is null only for empty inventory. Quote strings must be exact substrings of the actual response; omitted finding IDs must exist in the matching key. A key is non-exhaustive and the evaluator must credit defensible alternatives it did not anticipate. Findings are semantic guides, not counted points. Critical failures require an affirmative endorsed harmful claim/action with exact quote and explanation; rejecting a dangerous baseline, omission, discussing uncertainty or refusing deployment is never sufficient. For each affected dimension compute effective=min(raw, each applicable cap). Do not propagate a cap to other dimensions. No weighted aggregate, sum, average, overall pass/winner or checklist percentage.

Future score validation must verify scenario/run/response/packet/freeze/settings hashes, registered distinct evaluator identity and conflict attestation, exact quotes, finding/failure references, null applicability and mechanical caps. This package supplies schemas only for future records, not sample or fake records. Semantic correctness and attestation honesty still require actual independent review. Retain adjudication disagreements without overwriting; do not change frozen keys after responses are seen. Report per-case dimensions and regressions, read/latency/completion costs, failures and unscored cells, uncertainty, missing attestation and residual leakage limits. Structural validation or a conceptual walkthrough is not measured decision-quality improvement.

## Freeze and verification
Every file except freeze-manifest.json is listed with SHA256 in that manifest, including this protocol, the executable verify.py, tests and schemas. Its benchmark_id is AU-v2 and its files mapping has canonical relative paths as keys and lowercase 64-hex SHA256 strings as values. The manifest is exclusively created once with binary exclusive-open after structural authoring checks and before any model test. Its external SHA256 is the anchor; it cannot authenticate itself. verify.py requires --expected-manifest-sha256 SHA and verifies exact file inventory, file-byte hashes, traversal/symlink exclusion, strict JSON, supported schema shapes and cross-file references. It does not write a manifest or mutate files. These operations do not execute ER, call models, build scoring packets, score responses or register an execution. Run with python3 -B to prevent bytecode artifacts in the frozen package. Tests use cleaned, temporary synthetic mutations under this package directory and must not overlap verification of the original tree.

After freezing, do not edit/re-freeze any file. Fixes or exposed-case replacements require a separately versioned cohort and preserved prior anchor. Filesystem permissions are not adversarial write-once storage: exclusive creation and externally recorded hash provide the local integrity contract; an operator should preserve the anchor outside the repository. The validator supports only explicitly enumerated JSON Schema keywords and is not a general JSON Schema engine. JSON schema cannot enforce semantic truth, isolation, model distinctness or privacy.
