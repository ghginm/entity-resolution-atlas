# Repository-local scope specification

## Purpose and authority

Atlas helps an agent reason about unfamiliar Entity Resolution (ER) projects through **problem → decision → alternatives → trade-offs → evaluation → research**. It is reusable knowledge, not a matching engine, dataset, production instruction or universally preferred blueprint. A project's facts, constraints and user authorization govern implementation outside this repository.

This document, [AGENTS.md](AGENTS.md), [SCHEMA.md](SCHEMA.md), and the [evidence policy](references/evidence-policy.md) are the self-contained maintenance contract. The original build instruction is unavailable and is not claimed to be reproduced exactly. Historical reconciliation (source repository only) records its influence without making access to it necessary. A new explicit user instruction can authorize a bounded extension; historical drafts cannot.

## Knowledge responsibilities

Exactly five primary object types are retained:
- **Decision:** an actual design question, competing solution families, prerequisites and selection criteria.
- **Solution:** a mechanism, assumptions, variants, applicable conditions, failures, alternatives, evaluations and component interactions.
- **Architecture:** a composable configuration across independent topology, scoring, resolution and lifecycle choices, with artifact contracts and failure containment.
- **Hypothesis:** an explicitly untested, falsifiable prediction, comparator, controls, labels, uncertainty, guardrails and next decisions.
- **Evaluation:** an output-specific estimand, denominator, label/sampling design, comparisons, biases, uncertainty and interpretive limits.

[Fourteen domains](taxonomy/overview.md) allocate ownership, not mandatory pipeline stages. Maps, indexes, guides, deep dives, source notes and benchmark artifacts are not new object types. Stable IDs, canonical paths, approved tags and relation directions follow the schema; author through the five templates (source repository only).

## Consumption and contribution

Use progressive retrieval: L0 compact discovery → applicable L1 domain indexes → selected L2 cards and relevant linked alternatives/evaluations → L3 only for unresolved detail. Know the target project's implementation before selecting methods. Explain missing facts instead of inventing them. [Module contracts](taxonomy/module-contracts.md) preserve scope, provenance, score meaning and unresolved cases across transitions.

Preserve all `dev_docs/` bytes and existing stable IDs/links. Check source support and label Atlas inference explicitly. Keep hard prerequisites distinct from optional context and conditional exclusions. Make targeted additions rather than filling all taxonomy mentions. Update generated navigation and scope manifests deliberately, then run both structural checks (source repository only) and substantive content review (source repository only). Length and keyword checks cannot prove scientific correctness.

## Historical v1.1 boundary and independent evaluation

The authorized v1.1 iteration adds a small connected set on identity semantics, resolution, master representation, reference construction and missed-candidate diagnosis; selective retrieval; and an isolated agent-utility benchmark (source repository only). It does not introduce an ER engine, train models, process ER datasets, add services or expand every domain.

Benchmark scenarios, answer keys, rubric and protocol are frozen before coverage authoring. Answer keys and results remain outside the retrieval corpus. Fresh comparable agent runs evaluate decision recommendations, not ER algorithm accuracy. Report failed, unexecuted and unscored work honestly; documentation integrity does not prove agent usefulness. The coverage matrix (source repository only) is a content-review judgment with explicit scope, not an empirical score.

## Authorized v1.2+ extension

The user's comprehensive expansion authorization supersedes the historical v1.1 stop/review restriction. Its exact text is retained in `validation/v1.2/authorization.txt`; ownership, continuation state and residual scope are in the v1.2 tracker (source repository only). Documentation waves cover acquisition/incomplete truth/experiments; architecture/modularity/rules/artifacts; selected algorithmic alternatives; bounded execution/monitoring/lifecycle/governance; and agent integration/retrieval safeguards. Earlier handoffs remain historical. Wave 3 review is author-only; Wave 4 has separate critique with integrating-author remediation, not attested distinct-model post-remediation approval. The final review (source repository only) preserves specialist gaps and separates documentation validation from unexecuted expanded-corpus utility, ER and engineering experiments.

The five types, fourteen domains, six architecture IDs, immutable historical inputs, independent evidence and frozen benchmark restrictions remain in force. Architecture/modularity/rule-engine material must use existing types and contracts, not a parallel Atlas. No new matching engine, model training, datasets, agent framework, vector database or RAG service is introduced. Expanded methods need an explicit evaluation route; near-duplicate concepts deepen an existing owner rather than multiply cards. No card, generic plan or benchmark result authorizes production changes.
