# Atlas scope

## Purpose and authority

Atlas helps an agent reason about unfamiliar Entity Resolution (ER) projects through **problem → decision → alternatives → trade-offs → evaluation → research**. It is reusable knowledge, not a matching engine, dataset, production instruction or universally preferred blueprint. A project's facts, constraints and user authorization govern implementation outside this repository.

This document, [AGENTS.md](AGENTS.md), [SCHEMA.md](SCHEMA.md), and the [evidence policy](references/evidence-policy.md) define the knowledge and evidence contract. Historical drafts add no requirements. Atlas is read-only reference knowledge; it supplies neither project facts nor authorization.

## Knowledge responsibilities

Exactly five primary object types are retained:
- **Decision:** an actual design question, competing solution families, prerequisites and selection criteria.
- **Solution:** a mechanism, assumptions, variants, applicable conditions, failures, alternatives, evaluations and component interactions.
- **Architecture:** a composable configuration across independent topology, scoring, resolution and lifecycle choices, with artifact contracts and failure containment.
- **Hypothesis:** an explicitly untested, falsifiable prediction, comparator, controls, labels, uncertainty, guardrails and next decisions.
- **Evaluation:** an output-specific estimand, denominator, label/sampling design, comparisons, biases, uncertainty and interpretive limits.

[Fourteen domains](taxonomy/overview.md) allocate ownership, not mandatory pipeline stages. Maps, indexes, guides, deep dives and source notes are supporting navigation and evidence, not new object types. Stable IDs, canonical paths, approved tags and relation directions follow the schema.

## Consumption

Use progressive retrieval: L0 compact discovery → applicable L1 domain indexes → selected L2 cards and relevant linked alternatives/evaluations → L3 only for unresolved detail. Know the target project's implementation before selecting methods. Explain missing facts instead of inventing them. [Module contracts](taxonomy/module-contracts.md) preserve scope, provenance, score meaning and unresolved cases across transitions.

Check source support and label Atlas inference explicitly. Keep hard prerequisites distinct from optional context and conditional exclusions. Navigation completeness, document length and structural checks do not prove scientific correctness or measured utility.

## Evidence and implementation boundary

Atlas covers identity semantics, retrieval, scoring, resolution, master representation, acquisition, evaluation, experimentation, architecture, execution and governance at explicitly documented depth. A taxonomy entry is not a complete method specification or a recommendation.

No local ER performance experiment is supplied as proof of these methods. External studies retain their populations, assumptions and limits. Report failed, unexecuted and unscored work honestly; documentation integrity does not prove agent usefulness. Project-specific evidence must support adoption, rejection or an inconclusive decision.

No card, generic plan or research result authorizes production changes. The consumer package is Markdown knowledge and navigation, not an ER engine, dataset, service or agent framework. Tools and scripts are not prerequisites for consumption.
